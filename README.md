# dsh-annotate

> 在 DSH Web 的对话里**选中一段文字加批注**，你发送下一条消息时，批注会**随那条消息一起交给模型**，模型按编号逐条回应。投递只认「这一步收到的输入按 `source.kind` 归属为你」：回合进行中新增的批注不会被打断中的步骤取走，自动续跑轮次与后台作业通知也不算。

## 这是什么

`dsh-annotate` 是一个 **DSH（DeepSeek Harness）Web 插件**，补上了「读长回复时想就某几句话提问」缺的那一环：

1. 你在回复里**选中一句话**；
2. 写下你的疑问或备注（也可以不写，只做标记）；
3. 继续正常打字提问、正常回车 —— **不需要把引文和批注手动抄进输入框**；
4. 插件在你那条消息真正进入模型前，把批注块**追加**到这条消息上，模型于是同时看到「你的问题」和「你标注的原文 + 批注」；
5. 模型的回复按编号逐条对照（`Annotation 1：…`）。

它是**纯插件**：`cordis.patch.yml` 只插入一行自己的 Host 行，不改动 DSH 本体的任何文件。

## 功能特性

| 能力 | 说明 |
|---|---|
| 选中即批注 | 在正文里选中文字，选区上方浮出一个小「批注」按钮；按钮会自动避开视口边缘，不遮挡发送键、侧边栏和输入框 |
| 徽标不压输入框 | 编号徽标画在固定浮层里；只有当**徽标自身**会落进输入区（或可测到的会话头部）遮挡带时才**整条不渲染**——**不挪坐标**，避免被误读成锚点漂移（0.7.0，代价见[缺陷与限制](#缺陷与限制)第 12 条） |
| 批注可留空 | 留空 = 只标记原文，不产生额外内容 |
| 就地读批注 | 点原文旁的**编号徽标**，就地弹出卡片：编号、状态、原文、你写的批注，以及【跳回原文】【在右栏查看】【重新投递】（仅已送达的批注）【删除】 |
| 原文高亮 | 用 **CSS Custom Highlight API** 高亮，**不改写消息 DOM**（不往消息里注入节点、不改动已渲染的节点树）。注意这说的是 DOM：投递给模型时批注块是**另一条消息**（`source.kind` 不是 `user`），不改你那条消息的正文，见[缺陷与限制](#缺陷与限制)第 1 条 |
| 输入框右侧芯片 | 输入框工具栏最右侧、发送键左边显示 `✎ ×N`，一眼看出「还有 N 条批注待发送」；没有批注时**完全不占位** |
| 右侧栏管理页签 | 点芯片打开右侧栏的「批注」页签：全部批注可**回看 / 编辑 / 删除 / 跳回原文 / 重新投递 / 清空已送达 / 刷新**；右侧栏「+」引导页里也有入口 |
| 跨会话持久化 | 批注存在 Host 端 `$DSH_HOME/annotations/annotations.json`，跨会话、跨重启保留，且不污染任何工作区 |
| 重启后自动回来 | 重启 DSH 再打开同一会话：芯片与右栏列表立刻恢复；原文高亮与编号徽标**按引文重新定位**，若原文所在消息尚未加载，滚动到它出现时自动补上，不必手动刷新 |
| 编号全会话稳定 | 面板里的 3 号，就是模型回复里的 `Annotation 3`；不会出现「面板 5 号 / 回复 1 号」的错位 |
| 只投递一次 | 批注在投递后标记为「已送达」，同一回合的后续步骤不会重复携带；投递本身只发生在**载有归属给你的输入**的那一步（0.7.0） |
| 可重新投递 | 已送达的批注可在**弹卡**或**右栏列表**里点【重新投递】：它回到「待发送」，随你下一条消息再走一遍。注意这是「再发一次」，不会把已经进日志的那段文字撤回 |
| 模型可主动重读 | 注册了 `annotation` 工具：`list` 重新读取，`resolve` 标记已答复（上下文被压缩后特别有用） |
| 刷新后仍能定位 | 引文按**空白归一化**的全文索引重新定位：跨 `<strong>`、行内代码等多节点选区的引文也能找回，且一次重建只扫一遍文档 |
| 重复引文不错位 | 创建批注时就把「这是该引文的**第几次出现**（0 基，第一次即 0）」从活动选区捕获下来、随记录持久化（0.6.0）；重定位与【跳回原文】优先用它，同一处重复批注两条都记 0，各自锚定。只有没有该字段的旧记录才退回「按创建顺序」的老办法 |
| 接口双闸 | 本地 HTTP 接口要求回环 `Host`，并且要求每次启动随机生成、只注入到本进程所服务页面的一次性令牌 |
| 中英双语 UI | 文案跟随 DSH 的语言设置实时切换 |

## 安装与卸载

### 从 GitHub 安装

```sh
dsh plugin --profile web add github:RSoulYu/dsh-annotate
```

### 从本地目录安装（开发调试）

```sh
dsh plugin --profile web add /path/to/dsh-annotate
```

### 用插件管理器安装

在 DSH Web 的「设置 → 插件」里，用 `install_bundle` 指向本仓库的**绝对路径**即可。

### 卸载

```sh
dsh plugin --profile web remove dsh-annotate
```

### 关于重启

| 你改了什么 | 需要做什么 |
|---|---|
| 改浏览器半（`client.js`） | 浏览器 **Ctrl+Shift+R** 硬刷新即可（客户端模块每次请求都从磁盘重读） |
| 改 Host 半（`index.js`） | **重启 `dsh web`**。本 profile 默认关闭模块热替换（`hmr.root: []`），Host 模块只在启动时加载 |
| 安装 / 卸载插件本身 | 新 bundle 会热挂载；替换已安装的包需要重启 |

> 想让 Host 半也支持热更新：在 `~/.dsh/profiles/web/cordis.patch.yml` 里把 `hmr` 那一条改成 `config: { root: ["."] }`，重启一次后生效。

## 使用方法

### 1. 加一条批注

选中对话里的任意文字 → 点选区上方浮出的「批注」→ 写内容 → **`Enter` 保存**。

| 按键 | 行为 |
|---|---|
| `Enter` | 保存（留空 = 只标记原文） |
| `Shift+Enter` | 换行 |
| `Esc` | 取消 |

保存后：原文被高亮，左侧出现编号徽标。

### 2. 读一条批注

点**编号徽标** → 就地弹出卡片，显示原文与批注内容。卡片上的按钮：

- **跳回原文** —— 把这条批注对应的原文滚动到视口中央
- **在右栏查看** —— 打开右侧栏页签并定位到这一条
- **重新投递** —— 只对「已送达」的批注出现：把它放回「待发送」，随你下一条消息再交给模型
- **删除** —— 删除这条批注

点卡片以外的任意位置、或滚动页面，卡片自动关闭。

### 3. 打开管理面板

点输入框工具栏右侧的 **`✎ ×N`** 芯片 → 右侧栏弹出「批注」页签。

页签里可以：逐条**编辑**批注内容、**删除**、**跳回原文**、**重新投递已送达的批注**、**清空已送达**、**刷新**。

### 4. 发送

像平时一样打字、按回车。**你不需要做任何额外操作**，也不用把批注块拼进输入框。发送后转录里会**多出一条注入上下文行**（就是你那条消息下面单独的一行，标明来自本插件），而**你自己的气泡仍然只有你自己写的字**。这块文字确实会进会话日志、也确实会被模型读到 —— 细节与后果见[缺陷与限制](#缺陷与限制)第 1 条。

若模型正在跑，你在这一回合进行中新增的批注**不会**被本回合的后续步骤取走 —— 它会等你下一次真正发出消息时再一起送（0.7.0 的行为变更与代价见[缺陷与限制](#缺陷与限制)第 8 条）。

### 5. 重启之后

批注不会因为关掉 DSH 而消失：它们存在 Host 端文件里，与你在 DSH 里做的其它改动无关。

重新打开同一个会话时：

- 输入框工具栏右侧的芯片、右栏「批注」页签里的列表与逐条状态，立刻恢复；
- 原文高亮与编号徽标按**引文**重新定位；
- 如果某句原文所在的消息还没加载（历史分页），该条会在面板里标为「原文未在视图中」，**滚动到那段回复时高亮与徽标会自动补上**；
- 已经在「已送达 / 未删除」状态的批注不会被重复发送（想让它再走一遍，就在弹卡或右栏里点【重新投递】，它会回到「待发送」）。

### 6. 读回复

模型会按编号逐条回应：

```
Annotation 1：……（对应编号 1 的批注）
Annotation 3：……（对应编号 3 的批注）
```

## 批注块长什么样

Host 在 `agent/pre-step` 阶段，把下面这个块作为**一条独立消息**放在进入该步的那条用户消息**之后**（你那条消息一个字节都不改）。这里有个前提（0.7.0）：只有**这一步收到的输入按 `source.kind` 归属为你**（`source.kind === 'user'`）时才会带上这个块 —— 自动续跑轮次（`source.kind === 'goal'`）、后台作业通知（`source.kind === 'tool-jobs'`）等非用户步骤不再携带它。这几条批注要等**会话日志里真的出现这条带块的消息**才算送达：`agent/pre-step` 返回之后，循环还要过一道中止检查、再跑一次 `prepareRequest`，这中间被停止或失败，消息就不会进日志，块也就没送到 —— 这几条会留在「待发送」，随你下一条消息再走一次。

```
—— 批注（共 2 处，编号 1、3）——

1. 原文：「被批注的那句话」
   批注：这里我不太确定，能展开讲一下吗？

3. 原文：「另一句话」
   批注：（未填写批注，只标记了原文）

请用「Annotation 1：…」「Annotation 3：…」的格式逐条回应；不要复述原文，先直接回答问题，需要时再引用被批注的句子。
```

几个刻意的设计：

- **编号是会话内稳定编号**，不是「这一批的第几条」，所以面板、徽标、回复里的编号始终指同一个东西；
- **开头是空行 + 分隔标题行**，不会和你的原文粘在一起；
- **原文用 `「」` 包裹并压平空白**，避免引用块里出现奇怪的换行；
- 明确要求**不要复述原文**，减少模型把上下文再抄一遍的浪费。

## 工作原理

```
┌───────────────────────── 浏览器半 client.js ─────────────────────────┐
│  shell.overlay                                                        │
│    ├─ 选中工具条 / 批注编辑器 / 编号徽标 / 徽标弹卡 / 轻提示          │
│  conversation.input.right                                             │
│    └─ 「✎ ×N」芯片  ──点击──▶ ctx.sidebarRight.openTab('dsh-annotate') │
│  sidebar.right.pane.tab (key = dsh-annotate)                          │
│    └─ 管理面板：列表 / 编辑 / 删除 / 跳回 / 重投 / 清空                │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ POST /plugins/dsh-annotate/api
                                │ (x-dsh-annotation: 1, 仅回环 Host)
┌───────────────────────────────▼─────────── Host 半 index.js ─────────┐
│  AnnotationStore → $DSH_HOME/annotations/annotations.json             │
│  agent/pre-step  → 把待发送批注作为独立消息插到用户消息之后            │
│  session/event   → 核销：日志里出现带块的消息，才标「已送达」          │
│  tools.register  → annotation 工具（list / resolve）                  │
└──────────────────────────────────────────────────────────────────────┘
```

### 为什么不用「往输入框里拼文本」

往受控编辑器里写文本、再拦截回车提交，是最直观、也最脆的做法：编辑器会在下一次提交时覆盖掉外部写入，批注**静默丢失**，而且不同 DSH 版本的输入框 DOM 一直在变。

本插件换了一条路：

- **不碰输入框**。批注始终作为 Host 端数据存在，只有在消息**即将进入模型**时才拼装；
- **不依赖消息 DOM**。高亮走 CSS Custom Highlight API，编号徽标走 `shell.overlay` 的悬浮层，消息内容一个字节都没改；
- **只依赖官方扩展点**。用到的扩展点全部来自 DSH 自身的服务与插槽契约，DSH 升级时失效面小得多。

### 用到的官方扩展点

| 侧 | 扩展点 | 用途 |
|---|---|---|
| Host | `agent/pre-step`（waterfall） | 在消息进入模型前追加批注块 |
| Host | `session/event` | 核销投递：只有日志里出现带批注块的那条 `user/message` 才算送达 |
| Host | `ctx.tools.register` | 注册 `annotation` 工具 |
| Host | `ctx.inject(['webServer'])` + `webServer.register` | 提供浏览器半调用的 JSON 接口 |
| Host | `node:fs/promises` | 原子写入（临时文件 + rename）批注存储 |
| Client | `shell.overlay` | 工具条、编辑器、徽标、弹卡、轻提示 |
| Client | `conversation.input.right` | 输入框工具栏右侧的芯片 |
| Client | `sidebar.right.pane.tab` + `sidebarRightTabs.register` | 右侧栏「批注」页签（两段式注册） |
| Client | `ctx.sidebarRight.openTab` | 打开页签并展开右栏 |
| Client | `ctx.locale` | 中英文案 |

**Host 半不 import 任何 `@deepseek-ai/*` 包**（工作区安装的 bundle 在 profile 里解析不到它们），运行时只用 `node:*` 内建模块；浏览器半只用 `require('react')`，不 import Harness 客户端包。

## HTTP 接口

浏览器半只用一个接口。它绑定在回环地址上，并要求一个**自定义请求头** —— 跨站页面无法在没有预检的情况下带自定义头，而该路由不响应预检请求。

```
POST /plugins/dsh-annotate/api
Headers: content-type: application/json
         x-dsh-annotation: 1
```

| `action` | 载荷 | 返回 |
|---|---|---|
| `list` | `{ sessionId }` | 该会话的全部批注（含稳定编号与状态） |
| `create` | `{ sessionId, annotation: { sessionId, quote, note, origin, occurrence? } }` | 新建的批注 + 该会话列表。`occurrence` 是「这条批注选中的是该引文的第几次出现」（0 基，可选）：浏览器半在编辑器打开时从活动选区捕获、保存时发出；非有限非负整数一律按缺省处理 |
| `update` | `{ id, patch: { quote?, note? } }` | 更新后的批注 + 该会话列表 |
| `redeliver` | `{ id }` | 该会话列表；该条回到「待发送」，投递收据（`deliveredAt`/`deliveredTurn`）被清掉，下一条消息会重新携带它 |
| `delete` | `{ id }` | 该会话列表 |
| `clear-delivered` | `{ sessionId }` | 删除条数 + 该会话列表 |

失败统一返回 `{ "ok": false, "error": "…" }`；非回环 Host 或缺少请求头返回 `403`。

## Agent 工具 annotation

模型侧可以随时调用（例如上下文被压缩之后重新读取）：

| 参数 | 说明 |
|---|---|
| `action: "list"` | 返回当前会话的批注；`includeDelivered: false` 只看待发送的 |
| `action: "resolve"` | 把批注标记为已答复；`ids: [...]` 只标记指定几条，省略则标记全部待发送的 |

返回里带 `revision`（Host 半的代码修订号），便于确认运行中的进程到底加载了哪一版。

## 数据与隐私

| 项目 | 说明 |
|---|---|
| 存储位置 | `$DSH_HOME/annotations/annotations.json`（默认 `~/.dsh/annotations/annotations.json`），权限 `0600` |
| 存储格式 | `{ "version": 1, "annotations": [ { id, sessionId, quote, note, status, origin, occurrence?, createdAt, updatedAt, deliveredAt, deliveredTurn } ] }`；`occurrence`（0.6.0 起）只在这条批注确实捕获到序号时写入 |
| 写入方式 | 先写临时文件再 `rename`，避免半截文件；并发写串行化 |
| 容量上限 | 每个会话最多 400 条；超出时**优先清理最旧的「已送达」批注**，待发送的永不丢弃 |
| 单条长度 | 原文 2000 字符、批注 4000 字符（超出截断）；请求体上限 512 KiB |
| 接口鉴权 | 回环 `Host` + 每次启动随机的一次性令牌（令牌只出现在本进程渲染的 HTML 里，不进日志、不落盘） |
| 网络行为 | **没有任何外发请求**。插件不访问互联网，只写本地文件、只服务本机浏览器 |
| 是否进入会话日志 | **会。** 批注块作为**一条独立消息**（`source.kind` 为 `dsh-annotate`，不是 `user`）进入会话日志，转录里渲染成**注入上下文行**，不会并进你自己的气泡；你那条消息本身不变（见[缺陷与限制](#缺陷与限制)第 1 条） |
| 删除 | 面板里逐条删除 / 清空已送达；彻底清空直接删掉 `annotations.json` 即可 |

## 优点

1. **批注不会丢，也不冒充你的话**。投递发生在消息进入模型的瞬间，与输入框、DOM、时序解耦 —— 这三样正是「标了但发不出去」的常见根因；「已送达」是核销过的状态（见下）；而你那条消息的正文一个字节都没被改，气泡里始终只有你自己写的字。而且「已送达」是**核销过**的状态：只有日志里真的出现了那条带批注块的消息，这几条才算送达；在块写进日志**之前**被停止、或请求在准备阶段就失败时，它们仍然停在「待发送」，下一条消息会再带上它们 —— 而且只有**载有归属给你的输入**的那一步才会带走它们（0.7.0，见[缺陷与限制](#缺陷与限制)第 8 条）。
2. **零侵入**。不改 DSH 本体，不给消息 DOM 注入节点，不劫持键盘事件（`Enter` 只在批注编辑器自己获得焦点时才被消费）。
3. **模型拿到的上下文干净且可读**。批注块成段、带编号、带原文引用，并明确要求不复述原文。
4. **可回看**。批注是持久数据，不在「发送即消失」的草稿里；跨会话、跨重启都在。
5. **模型可以主动补读**。`annotation` 工具解决了长会话里「早期批注被压缩掉」的问题。
6. **不占地方**。没有批注时，界面里**没有任何**本插件的元素。
7. **布局风险低**。全部界面都住在宿主明确为插件预留的位置（`shell.overlay`、`conversation.input.right`、`sidebar.right.pane.tab`），不去猜别人的 DOM 结构。
8. **可验证**。67 个单测覆盖三段：Host 投递链路（块的独立消息形状与 `user/message` 契约、你那条消息不被改写、只投一次、跨会话隔离、`reject` 不改写、工具读写、已送达批注的**重新投递**与随之而来的再投递，以及**核销式送达**：未进日志不算送达、中止后下一条消息重投、**已核销的送达不因随后的中止而回退**、有未核销的块时不重复注入，以及 0.7.0 的**投递门控**：无用户归属输入的一步不注入/不核销/不读存储、`source.kind === 'goal'` 的自动续跑不消费、决策里被别家塞进来的用户归属消息不算数、消息列表非数组时保守拒绝并留痕、wire 列表失主时不挂块并留痕，还有创建时 `occurrence` 字段的四条链路透传与非法值丢弃）、接口鉴权闸门（回环判定、令牌要求、DNS rebinding 拒绝）、引文定位与徽标遮挡判定核心（跨节点、空白差异、重复引文按序、**同一引文的 0 基序号表**、**位置 → 该位置属于第几次出现**、**创建时捕获优先于回退表**，以及 0.7.0 的 `badgeBand`/`badgeBox`/`badgeVisibleIn`：遮挡带两条边的取值与 152 兜底、实测底边优先、贴边算带外、退化输入不抛错、带上下边倒置时降级为只留底边，外加「整条不渲染且坐标不挪」的源码契约）。CI 每次 push 都跑。

## 缺陷与限制

诚实的清单，按「大概率会遇到」排序：

1. **批注块是会话日志里的一条独立消息，但不是你的话。** 块作为**它自己的 `user/message` 事件**进入日志（`source.kind` 为 `dsh-annotate`），转录里渲染成注入上下文行；**你的气泡里只有你自己写的字**，你那条消息的 `content` 一个字节都没被改。
   - 批注本身持久化在 `$DSH_HOME/annotations/annotations.json`：重启 DSH 后打开同一会话，芯片、右栏列表、逐条状态都还在，原文高亮与徽标会按引文重新定位（原文所在消息未加载时会随滚动补上）。这一层与投递无关。
   - 投递发生在 `agent/pre-step`：块被**插到**进入该步的那条用户消息之后，成为列表里的下一条消息。DSH 的循环把 `decision.messages` 逐条 `append` 进会话日志，聊天界面再按事件类型与 `source.kind` 决定渲染方式：`source.kind === "user"` 才画成你的气泡，其它 kind 一律画成注入上下文行（`@deepseek-ai/dsh-client-ui-chat` 的 `messageDefinition` → `contextMessage`）。所以块进日志、模型读得到，但不冒充你写的字。
   - 不能把它换成「只给模型看、不进日志」：DSH 要求**模型可见内容必须走会被记录的信道**，`agent/pre-step` 只能改写将要被记录的消息，没有模型可见但不入日志的旁路。写一个全新事件类型同样不行 —— 未知事件只有在信封带 `ignorable: true` 时才被接受，而实时 `Session.append()` 无法设置该标记，硬写会让会话**拒绝重新打开**。
   - 由此有两个后果，用之前请知道：
     - **删掉一条「已送达」批注，不会把它从转录里撤回。** 那段文字已经是一条独立消息；面板与 JSON 删掉的只是批注记录本身，以及徽标与高亮。
     - **导出、分享或复制那条会话时，批注原文与批注内容会一起被带走。** 这一条和「数据与隐私」表里的网络行为无关（插件自身零外发请求），只取决于你拿这条会话去做什么。
   - 反过来也有两个好处：因为块就落在转录里，回复点「重新生成」「分叉」时模型**会**再看到它一遍 —— 这是 `annotation` 工具之外的第二条重读路径；第三条是你主动点【重新投递】（0.5.0），它把已送达的批注放回「待发送」，下一条消息再带一次。注意这一条是「再发一次」而不是「撤回再发」：那段原文与批注会被模型读第二遍，转录里也会再出现一个注入上下文行。
2. **Host 半的改动需要重启才生效。** 本 profile 关闭了模块热替换；改 `client.js` 刷新即可，改 `index.js` 必须重启 `dsh web`。开发时这点比较烦。
3. **刷新后靠引文重新定位。** 徽标与高亮依赖浏览器里的实时 `Range`；刷新后按**空白归一化**的全文索引重新匹配，因此跨节点选区（`<strong>`、行内代码等）与空白差异（DOM 里的换行缩进 vs 你复制到的文本）都能找回。同一句引文被批注多次时，**每条批注的真实出现序号在创建那一刻就被捕获**（0.6.0）：浏览器半打开编辑器时从活动选区（`Range` 起点）算出「这是该引文的第几次出现」（0 基），保存时随 `create` 请求发出，Host 半把它存进 JSON，**重定位与【跳回原文】优先用这个真值**。于是「同一处重复批注两条」不再失锚 —— 两条都记 0、都锚到那一处；「两处各批注一条」仍是 0 与 1、各就各位（0.5.0 的修复不回退）。没有该字段的旧记录（0.5.0 及更早写下的）退回**创建顺序表**，且这张回退表只在「没有该字段的记录」之间建立：知道自己是第几次的新记录不占回退序号，也不会把旧记录挤到别处。这张回退表还有一个**反方向**的代价，出现在新旧记录混用的会话里：当引文在文档中出现 **2 次**时，一条没有 `occurrence` 字段的旧记录如果原本批注在**第二处**，回退表会把它算成 0，于是**静默落在第一处**（0.5.0 同输入亦如此，非本次回归）—— 把那条旧批注删掉、在原位重新批注一次，就能带上真值。若打开编辑器时取不到序号（选区所在的节点已被重渲染替换等），就**不写**该字段 —— 宁走回退表，也不落一个猜出来的序号；拿着序号定位不到时保持「原文未在视图中」，交给既有的自动重试，不会去扫其它副本。**但引文在当前页面里根本不存在**（例如被虚拟滚动卸载的历史消息）时仍然定位不到 —— 面板里的全文始终保留，该条会标为「原文未在视图中」，滚动到那次出现时自动补上。0.6.0 的绘制面同样只能人工在浏览器里确认：**浏览器绘制面无法自动验证** —— 高亮与徽标落在哪一处、【跳回原文】滚到哪、状态如何流转，单测钉得住的是纯函数与持久化字段，钉不住绘制。
4. **高亮依赖较新的浏览器特性。** CSS Custom Highlight API 需要 Chromium 105+；不可用时只是没有底色高亮，功能不受影响。
5. **只支持 Web 平台。** 没有 TUI/终端版本（`dsh.client.platform` 声明为 `web`）。
6. **只处理文本。** 图片里的文字、工具调用卡片内的结构化内容不能选中批注（工具输出里的纯文本可以）。
7. **编号按会话独立。** 每个会话各自从 1 开始，跨会话不连续。
8. **投递只发生在「载有归属给你的输入」的那一步（0.7.0 的行为变更）。** 判据是该步**领取到的输入**里有没有 `source.kind === 'user'` 的消息，而不是「你亲手打字」：`/plan <text>` 的 steer、`/goal` 的附件、agent-teams 回灌的斜杠命令（以及子代理在子会话里的委派提示）同样按此归属，因此它们会带上块；而自动续跑轮次（`source.kind === 'goal'`）、后台作业通知（`source.kind === 'tool-jobs'`）、运行时上下文（`runtime-context`）等非用户步骤**不会**再消费批注。代价是：**回合进行中新增的批注要等你下一次真正发出消息才送达** —— 在这之前它停在「待发送」（模型可以用 `annotation` 工具主动读到），不会跟着模型当前这一步走；非用户步骤也不会把它取走。如果模型正在忙、你的消息进了队列，批注会跟随那条排队消息在被处理时一起送达；如果那条消息一直没被处理，批注会一直停在「待发送」。送达的判定点仍是**那条消息真的写进了会话日志**：在块写进日志**之前**中止、或请求在准备阶段就失败时，这一步不写日志，批注退回「待发送」并在你下一条消息上重新携带；反过来，块**已经写进日志之后**再按停止，不会把已送达的批注打回「待发送」（0.6.0 补上了这条回归测试）。代价是存在一个很窄的重复窗口 —— 块已经进了日志、但进程在把这批批注写成「已送达」之前退出，下次启动时它们仍显示为「待发送」，于是会再发一次。
9. **本地接口的鉴权边界。** 现在有两道闸：`Host` 必须是回环地址（挡 DNS rebinding），且请求必须携带**本进程启动时随机生成、仅写入本进程所服务页面 boot payload 的一次性令牌**（挡同机的其它网页与脚本）。但**同一用户下的本地进程仍可直接读 `~/.dsh/annotations/annotations.json`**（`0600`）—— 这是文件权限层面的边界，不归本插件管。
10. **明文存储。** 批注明文落盘（`0600`）。如果批注里粘了敏感信息，它就会以明文留在 `~/.dsh/annotations/` 里，需要手动或通过面板删除。
11. **未在 macOS/Windows 上实测。** 代码只用 `node:*` 与浏览器 API，理论上跨平台，但目前只在 Linux（Arch + Chromium）验证过。
12. **徽标遮挡裁剪：徽标自身落进遮挡带时，这一条整条不渲染（0.7.0）。** 判据是**徽标自己的盒**（`rect.top - 9` 起、18px 高），不是整条引文；命中就整条不渲染，**绝不挪坐标**（挪了会被误读成「锚点漂移」）。代价与已知限制：
    - 引文顶部滚到输入区背后（徽标盒因此压住输入区或高过会话头部）时，该条徽标在这个滚动位置整条不渲染，转录里暂时点不开它 —— 此时仍可从右侧栏「批注」页签里跳回原文 / 编辑 / 删除 / 重新投递。**注意**：引文尾部跨过输入区顶边、而徽标自身仍在带外时，徽标照常渲染（这正是 0.7.0 特意收紧的地方：不因为引文一部分被压住就把整条徽标藏掉）；
    - **极端窗口尺寸**下（会话头部 + 输入区高度 ≥ 视口高）遮挡带两条边会倒置：0.7.0 的处理是**丢弃头部边、只保留输入区边**（不凭空制造第二条边），所以不会整层消失；只有当**输入区本身比视口还高**（底边落到视口上方）时，**所有徽标都会被隐藏** —— 这是已知限制；
    - **绘制面无法自动验证**：单测只钉住纯函数判定（遮挡带两条边的取值与 152px 兜底、实测底边优先、徽标盒与带相交、贴边算带外、退化输入不抛错），真实绘制位置与点击要人工核对：① 把一条引文上滚到输入框背后 —— 徽标应消失，而输入框仍能点入聚焦（不被徽标抢走点击）；② 再滚回来 —— 徽标应立即恢复，编号与位置不变（无漂移）；③ 把输入框写成多行抬高输入区 —— 徽标消失的高度阈值应随之变化。若某个宿主版本不满足这些预期，请按缺陷报告。
    - 遮挡带依赖宿主 CSS 变量 `--dsh-composer-height`（写在 `[data-conversation-scroll]` 上；读不到时用宿主自己的 `152px` 兜底，再读不到底边位置时退化为按视口高推算）；头部边依赖 `[data-conversation-scroll]` 容器，取不到时**不裁头部**（不会去猜一个头部高度）。

## 常见问题

**Q：批注发出了，但模型没按编号回应？**
A：批注块是随消息发的，模型可能选择合并回答。可以明确要求「逐条回应」；或直接调 `annotation` 工具让模型重读一遍。

**Q：芯片不见了？**
A：芯片只在当前会话**存在批注**时出现；「已送达」的批注也会让它保留（显示总条数）。清空已送达后如果一条不剩，它就消失了。

**Q：点芯片右栏没反应？**
A：右栏页签依赖 `dsh-client-ui-sidebar-right`。若该插件被禁用，芯片会提示「右侧栏不可用」。

**Q：刷新后高亮位置不对？**
A：见「缺陷与限制」第 3 条 —— 是按引文重新匹配的。跨节点的长选区最容易偏。

**Q：同一句引文就在同一处标了两条，第二条一直显示「原文未在视图中」？**
A：那是 0.5.0 的回归，0.6.0 已修：创建时就把「这是该引文的第几次出现」捕获进记录，同一处的两条都记 0，各自锚定到那一处。如果第二条是升级前就建好的旧记录（没有该字段，仍走创建顺序回退表），删掉重新批注一次即可带上真值。

**Q：能批注我自己的消息吗？**
A：可以，助手回复和你的消息都能选中批注（面板里会标注来源）。

**Q：会消耗额外 token 吗？**
A：批注块只在**你实际发送了批注的那条消息**上出现，长度约等于原文 + 批注内容；没有批注时零开销。
