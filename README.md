# dsh-annotate

**在 DSH Web 的对话里选中一段文字加批注，它随你下一条消息一起交给模型，模型按编号逐条回应。**

**简体中文** | [English](README.en.md) · [CHANGELOG](CHANGELOG.md)

## 这是什么

读长回复时想就其中几句话提问，通常得手动把引文抄进输入框。本插件补上这一环：

1. 在回复里**选中一句话**，写下批注（也可留空，只做标记）；
2. 继续正常打字、正常回车——**不需要手动抄引文**；
3. 插件在你那条消息进入模型前，把批注块**作为一条独立消息**追加在其后；
4. 模型按 `Annotation 1：…` 的编号逐条回应。

纯插件：`cordis.patch.yml` 只插入一行自己的 Host 行，不改动 DSH 本体的任何文件。

## 安装

```sh
dsh plugin --profile <profile> add github:RSoulYu/dsh-annotate
dsh plugin --profile <profile> remove dsh-annotate    # 卸载
```

要求 DSH `0.2.0-rc.2`（用到的插槽与两段式注册契约以 0.2.x 为准，`0.1.x` 未适配）；「跳回原文」另外要求宿主的公开会话服务 `ctx.sessions`（`test/host-shape.test.mjs` 断言这组形状，宿主改了会显式失败）。改 `client.js` 后浏览器硬刷新即可；改 `index.js` 需重启 `dsh web`。

## 使用

| 操作 | 方式 |
|---|---|
| 加批注 | 选中文字 → 点浮出的「批注」→ 写内容 → `Enter` 保存（`Shift+Enter` 换行，`Esc` 取消） |
| 读批注 | 点原文旁的**编号徽标**就地弹出卡片：编号、状态、原文、批注，以及跳回原文 / 在右栏查看 / 重新投递 / 删除 |
| 管理 | 点输入框工具栏右侧的 `✎ ×N` 芯片，打开右侧栏「批注」页签：编辑 / 删除 / 跳回 / 重新投递 / 清空已送达 / 刷新 |
| 跳回原文 | 点「跳回原文」：原文已在页面里就直接滚到它；**原文所在的消息还没加载时，插件会通过宿主自己的分页动作把更早的历史加载进来**（宿主自己的「加载更早」按钮走的是同一条公开调用），再滚到原文。仍然找不到时该行会留下**持久**的原因、按钮保持可点，并在元素上写 `data-dsa-jump="failed:<原因>"` 与 `data-dsa-jump-pages`，不会只弹一句提示就结束 |
| 发送 | 照常打字回车。转录里会多出一条注入上下文行，**你自己的气泡仍然只有你写的字** |

模型侧可调用 `annotation` 工具：`list` 重新读取，`resolve` 标记已答复（上下文被压缩后尤其有用）。

## 能力

| 能力 | 说明 |
|---|---|
| 零侵入 | 不改 DSH 本体，不往消息 DOM 注入节点，不劫持键盘事件（`Enter` 只在批注编辑器获得焦点时被消费）；没有批注时界面里没有任何本插件的元素 |
| 原文高亮 | 走 **CSS Custom Highlight API**，不改写已渲染的消息节点树 |
| 跨会话持久化 | 批注存在 Host 端，跨会话、跨重启保留，且不污染任何工作区；重启后芯片与右栏列表立即恢复，高亮与徽标按引文重新定位 |
| 编号全会话稳定 | 编号在**创建时分配一次并随记录持久化**：删掉别的批注、或点【清空已送达】，都不会让还存在的批注改号；面板里的 3 号就是模型回复里的 `Annotation 3`，不会错位。**0.8.0 之前写入、没有编号的旧批注在插件启动时补号落盘**（补号前自动在同一目录留一份备份），所以旧批注同样不再前移 |
| 只投递一次 | 投递后标记「已送达」；已送达的可点【重新投递】放回待发送，随下一条消息再走一遍 |
| 重复引文不错位 | 创建时即捕获「这是该引文的第几次出现」并随记录持久化，重定位与跳回优先用它 |

## 工作原理

```
选中文字 ─▶ 批注存 Host 端 ─▶ agent/pre-step 追加独立消息 ─▶ 模型按编号回应
                                  └─ session/event 核销「已送达」
```

投递只认「这一步收到的输入按 `source.kind` 归属为你」：回合进行中新增的批注不会被打断中的步骤取走，自动续跑轮次与后台作业通知也不算。**送达的判定点是那条消息真的写进了会话日志**——在此之前中止，批注退回「待发送」。

用到的扩展点全部来自 DSH 自身的服务与插槽契约（`agent/pre-step`、`session/event`、`ctx.tools.register`、`webServer.register`、`shell.overlay`、`conversation.input.right`、`sidebar.right.pane.tab`、`ctx.locale`），不上游补丁，DSH 升级时失效面小。

## 数据与隐私

| 项目 | 说明 |
|---|---|
| 存储 | `$DSH_HOME/annotations/annotations.json`，权限 `0600`；先写临时文件再 `rename`，并发写串行化；给旧记录补号前会在同目录写一份 `annotations.json.migrate-0.9.0.bak`（`0600`，已存在的那一份不会被覆盖，且不会再建第二份） |
| 容量 | 每会话最多 400 条，超出时优先清理最旧的已送达批注，待发送的永不丢弃 |
| 长度 | 原文 2000 字符、批注 4000 字符（超出截断）；请求体上限 512 KiB |
| 接口鉴权 | 回环 `Host` + 每次启动随机生成、只注入本进程所服务页面的一次性令牌 |
| 网络 | **没有任何外发请求**，只写本地文件、只服务本机浏览器 |

## 缺陷与限制

1. **批注块是日志里的独立消息，但不是你的话。** 你那条消息的 `content` 一个字节都没被改，转录里渲染成注入上下文行。两个后果：**删掉一条已送达批注不会把它从转录里撤回**；**导出或分享该会话会一起带走批注原文与内容**（插件自身零外发，只取决于你拿这条会话做什么）。反过来，回复点「重新生成」时模型会再看到它一遍。
2. **Host 半的改动需要重启才生效。** 改 `client.js` 刷新即可，改 `index.js` 必须重启 `dsh web`。
3. **刷新后靠引文重新定位。** 按空白归一化的全文索引重新匹配，跨节点选区与空白差异都能找回；引文在当前页面不存在时（如所在消息还在已加载事件窗口之外）标为「原文未在视图中」，滚动到时自动补上。**「跳回原文」**在这种时候会先把更早的历史加载进来再落位（0.10.0）；仍不可达时给出 5 种持久原因之一并在 `data-dsa-jump` 上标明，按钮保持可点重试。**浏览器绘制面无法自动验证**——单测只钉得住纯函数、判定表与持久化字段。
4. **跳转有上限，越老的批注越慢。** 一次跳转最多向宿主请求 60 页（每页至少 50 条消息），连续 3 次请求后窗口仍无进展就停下并如实报告「宿主没有返回更早的历史」；等待在途页与重复揭示各自的帧预算也在有限帧内结束（分别报 `stalled` 与 `folded`），不会无限等。这是宿主公开动词决定的上限，不是为了快而去猜坐标：插件不新增依赖、不猜宿主内部 DOM 属性、不用 `loadThrough` 猜一个事件序号。**原文已经加载在页面里时不需要宿主**：这种情况直接滚动到原文，宿主会话服务缺失也照样跳得过去。
5. **仍可能跳不过去的场景（都会有持久原因，不会静默无动作）。** 原文在另一个视图（对话/轨迹）里；原文已被编辑或被上下文压缩删除；原文在宿主的折叠块里而平台的揭示事件没生效（`failed:folded`）；宿主没有提供会话服务（`failed:no-session`）；窗口长时间既忙又无进展（`failed:stalled`）；还有更早历史没加载完就用光了这一轮的页预算（`failed:budget`，再点一次会从已扩大的窗口接着找）。这几种状态下该行保留原因文案、按钮可点重试，元素上带 `data-dsa-jump="failed:<原因>"` 与 `data-dsa-jump-pages`。
6. **平台与范围。** 只支持 Web（无 TUI/终端版本）；只处理文本，图片里的文字与工具调用卡片内的结构化内容不能选中（工具输出里的纯文本可以）。编号按会话独立，每个会话的第一条批注是 1，跨会话不连续。编号是**创建时分配、此后不再改变**的身份：删掉一条批注或点【清空已送达】，都不会让还存在的批注改号（于是编号**不再连续**）。新编号取「现存最大号 + 1」——它不是永不回头的计数器，所以反复增删的会话不会把编号无限推高；也绝不会与**仍存在**的批注撞号，唯一会回到池子里的历史号，是被删掉的恰为当时**最大号**的那个（从 1、2、3 里删 3，下一条又拿到 3；删 2 则下一条是 4，**非最大号永不复用**）。**0.8.0 之前写入、没有 `number` 字段的旧记录在插件启动时补号落盘**——补的就是它当时按位置读到的号，所以删除更早的旧记录不再让后面的前移；补号只发生一次，补号前自动在同一目录留一份备份，补号失败时这次启动不写盘、下次启动重试。另有一条回退代价：**装回 0.8.0 之前的版本会把已落盘的 `number` 抹掉**（老版本的记录按固定键集重建、落盘又整份重写），那些批注会退回位置编号；装回 0.8.0 会保留已补的号，但不会再补新出现的旧记录，重新装回 0.9.0 时会再补一次（已存在的备份不会被覆盖）。
7. **投递只发生在「载有归属给你的输入」的那一步。** 判据是该步领取到的输入里有没有 `source.kind === 'user'` 的消息，而不是「你亲手打字」。代价是：**回合进行中新增的批注要等你下一次真正发出消息才送达**。存在一个很窄的重复窗口——块已进日志、但进程在写成「已送达」前退出，下次启动会再发一次。
8. **本地数据边界。** 回环 `Host` + 一次性令牌两道闸挡住同机的其它网页与脚本；但**同一用户下的本地进程仍可直接读取该 JSON 文件**——这是文件权限层面的边界，不归本插件管。批注明文落盘（`0600`），粘了敏感信息就会以明文留在 `$DSH_HOME/annotations/` 里，需手动或经面板删除。
9. **环境边界。** 高亮依赖 CSS Custom Highlight API（Chromium 105+），不可用时只是没有底色高亮，功能不受影响；代码只用 `node:*` 与浏览器 API，但**未在 macOS / Windows 上实测**。
10. **徽标遮挡裁剪。** 徽标自身落进输入区（或会话头部）遮挡带时，这一条**整条不渲染且不挪坐标**——此时仍可从右侧栏页签跳回原文 / 编辑 / 删除 / 重新投递。极端窗口尺寸下遮挡带两条边会倒置，处理是丢弃头部边、只保留输入区边。

## 开发

```sh
node --check index.js && node --check client.js   # 语法检查
node --test                                       # 单测（自动发现 test/）
DSH_ANNOTATE_HOST_ROOT=/usr/lib/node_modules/@deepseek-ai/dsh node --test   # 严格跑宿主形状断言
node --import ./test/freeze-clock.mjs --test      # 冻结 Date.now() 再跑一次
```

> 单测命令**不要带 `test/` 路径参数**：Node 22 会把它当模块路径去 `require` 而直接退出。

CI 在 Node 20 与 22 上各跑一遍。`anchor` 那组测的是**出货代码本身**：核心函数用 `@pure-anchor` 标记在 `client.js` 里圈出，测试取出源码直接求值，不会出现「测试全绿但线上是另一份实现」——跳转的判定表与驱动在同一片标记区里，因此同样按出货代码断言。`jump` 那组覆盖三条路径、5 个失败原因、在途页（宿主 `loadingOlder === true` 时 `loadOlder()` 是静默 no-op，因此只能等）与预算上限；新增逻辑不读墙钟，所以冻结 `Date.now()` 的那一次必须与常规运行结果一致。

`host-shape` 那组是一道**机械防线**：用例直接读宿主已发布源码，断言跳转依赖的公开形状（`ctx.sessions`、`binding`/`session`/`eventSource`、`loadOlder()`、`openState`/`hasMore`/`loadingOlder`、`revision`，以及「对话记录里没有 `IntersectionObserver`」「chat 不消费 `viewRequest`」两条负向事实）。宿主改了形状就**显式失败**，不会继续绿；宿主缺失同样失败。唯一的非验证路径是显式 `DSH_ANNOTATE_HOST_ROOT=absent`（GitHub CI 上无宿主，workflow 里显式设置），它会打印 `host shape check: skipped by DSH_ANNOTATE_HOST_ROOT=absent`，**不得**当作已验证。排障看浏览器 Console 的 `[dsh-annotate]` 前缀日志——交互处理器都有兜底，出错会打印并弹可见提示，不会静默失败。
